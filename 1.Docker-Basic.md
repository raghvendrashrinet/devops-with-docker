## Docker Architecture (The Engine)
The Docker Engine is a client-server application with three main components:
1.  **CLI Client:** The `docker` command you use in the terminal.
2.  **REST API:** The interface used by the CLI to talk to the daemon.
3.  **Docker Daemon (`dockerd`):** The background process that manages Docker objects like images, containers, networks, and volumes.

---

## Docker Service Management (systemctl)
On Linux systems, the Docker daemon is managed as a system service. Use these commands if Docker isn't responding or you need to change its boot behavior:

| Task | Command |
| :--- | :--- |
| **Check Status** | `sudo systemctl status docker` |
| **Start Docker** | `sudo systemctl start docker` |
| **Stop Docker** | `sudo systemctl stop docker` |
| **Restart Docker** | `sudo systemctl restart docker` |
| **Enable on Boot** | `sudo systemctl enable docker` |
| **Disable on Boot** | `sudo systemctl disable docker` |

---
### Process Monitoring (ps aux)
If you want to see the actual processes running on your Linux host, use:
* `ps aux | grep docker` — Lists all running processes related to Docker.
* **What to look for:**
    * `/usr/bin/dockerd`: The main Docker daemon.
    * `containerd`: The runtime that manages the container lifecycle.
    * `docker-proxy`: Handles network traffic for your containers.

## Basic Docker Commands

### Image Management
| Command | Shorthand | Description |
| :--- | :--- | :--- |
| `docker image ls` | `docker images` | List all local images |
| `docker image pull <img>` | `docker pull` | Download an image from a registry |
| `docker image rm <img>` | `docker rmi` | Remove an image (must stop containers first) |
| `docker image prune` | N/A | Remove "dangling" (unused/unnamed) images |

### Container Management
| Command | Shorthand | Description |
| :--- | :--- | :--- |
| `docker container run <img>`| `docker run` | Create and start a container |
| `docker run -d <img>` | N/A | Start a container in **detached** mode (background) |
| `docker container ls -a` | `docker ps -a` | List all containers (running and stopped) |
| `docker container stop <id>`| `docker stop` | Stop a running container |
| `docker container rm <id>` | `docker rm` | Remove a container |
| `docker container prune` | N/A | Remove all stopped containers |

### System & Daemon Cleanup
| Command | Description |
| :--- | :--- |
| `docker system prune` | **The "Nuke" Option:** Clears stopped containers, unused networks, and dangling images to free up space. |
| `docker container exec -it <id> bash` | Execute a command (like a shell) inside a running container. |

---
## Advanced Utility Commands (Bulk Actions)
Sometimes you need to stop or remove everything at once. You can nest commands using `$(...)`.

| Task | Command |
| :--- | :--- |
| **Stop all containers** | `docker stop $(docker ps -aq)` |
| **Remove all containers** | `docker rm $(docker ps -aq)` |
| **Remove all images** | `docker rmi $(docker images -q)` |

## Key Definitions
* **Image:** An **immutable** file/blueprint. It never changes once built.
* **Container:** A running instance of an image. It is an isolated environment.
* **Dockerfile:** The "recipe" used to build an image.
